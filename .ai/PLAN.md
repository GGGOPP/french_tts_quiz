# French A1–A2 Listening, Grammar & Production Quiz: Plan

## Context
This is a personal French practice app, a sibling of `Greek_tts_quiz`. The Greek app was vocab-only and built for a complete beginner. This one targets **A1–A2** for the user themselves. Their reading is better than their listening, and **grammar is their weakest area**. They will use it on both desktop and mobile. The aim is to train grammar, listening and English→French production, with sentences and phrases at the centre rather than single words.

Decisions made with the user:
- **Architecture as in the Greek app:** a static Vite + TypeScript site on GitHub Pages, with audio pre-generated by a Python (uv) pipeline using edge-tts, progress kept in localStorage, and Whisper QA.
- **Content:** an item bank of French sentences and phrases, each tagged with topic, level and grammar points. One audio clip serves several exercise modes. Claude drafts the content and the user reviews it.
- **v1 modes:** grammar cloze, dictée (hear French, type French), listen→meaning (hear French, type English), English→French production, and a numbers/time listening mode.
- **Accents are strict:** a missing or wrong accent counts as wrong, but the feedback labels it as an accent error. An accent-button row under every French input makes accents easy to type on desktop and phone.
- **LLM grading:** used for answers that can't be checked mechanically (English→French and listen→meaning). It goes through **OpenRouter**, using a key the user pastes into Settings on each device and that is stored in localStorage. The browser calls OpenRouter directly, with no backend. If there is no key, no network or an error, the app falls back to self-marking.
- **Choosing the grader:** an **offline benchmark** on a labelled test set compares Claude Haiku, Gemini Flash / Flash-Lite, GPT mini / nano, Mistral Small, and an open model (Llama or Qwen). The user then picks the default model at a checkpoint.
- **Not in v1:** minimal-pair "which did you hear" drills, two-voice dialogues, FSRS day-based spacing, pronunciation/speech input, an in-app model switch, and side-by-side grading.

Tools: Python 3.14 + uv (pipeline pinned to 3.12 for faster-whisper), Node 22, ffmpeg, git. The project folder is empty.

## Data format (YAML, so sentences can contain commas)
```yaml
# data/grammar/passe-compose-etre.yaml
point: passe-compose-etre
title: Passé composé with être
level: A2
rule: |                     # short rule card (markdown), shown on a wrong answer and in the browser
  Verbs of movement (aller, venir, partir…) and reflexive verbs take être. The participle agrees with the subject.
items:
  - id: pce-01
    fr: "Hier, elle {est allée|aller} au marché."   # {answer|hint}; answer alternatives with /
    en: [Yesterday she went to the market.]
    explain: aller takes être; feminine subject → allée
```
```yaml
# data/topics/restaurant.yaml
topic: Café & restaurant
items:
  - id: resto-03
    fr: Je voudrais un café, s'il vous plaît.
    en: [I would like a coffee please, I'd like a coffee please]
    alt_fr: [Je voudrais un café, s'il te plaît.]    # more accepted French for production
    level: A1
    grammar: [conditional-politeness]
    register: formal                                 # optional: tells the grader tu/vous matters
    notes: …
```
- The spoken text is `fr` with the brace markup resolved to the answer. Any item with braces gets the cloze mode, and every item gets dictée, meaning and production.
- A pytest validator checks the files: unique ids, well-formed braces, required fields, known grammar tags and a valid level.
- `items.json` = `{ topics, grammarPoints (with rules), items: [{id, fr, cloze?, en[], altFr[], level, topic|point, grammar[], register, notes, explain, audio, audioSlow}] }`.

## Grading rules
- **Shared French normalisation (`french.ts`):** NFC, lowercase, curly or straight apostrophes → `'`, non-breaking spaces and space before `?!:;` collapsed, and final punctuation ignored. **Accents and hyphens are kept** (strict).
- **Cloze:** after normalisation the answer must match one of the alternatives exactly, with no typo tolerance (`allez` ≠ `allons`). If it differs only by accents, it is still wrong, but labelled "accent". The feedback shows the full sentence, `explain` and the rule card, then plays the audio.
- **Dictée:** word-level alignment (edit distance over tokens, with `l'`/`j'` split as their own tokens). Each word is marked right, accent, wrong, missing or extra, and the answer counts as right only if every word is right. The feedback shows the diff and the English.
- **Listen→meaning:** first the Greek `grade()` against `en[]` (typo-tolerant English). If that doesn't match, the LLM decides, and if the LLM is unavailable, you mark yourself.
- **English→French:** first a strict local match against `fr` + `alt_fr`. If that doesn't match, the LLM decides, and if the LLM is unavailable, you mark yourself.
- **LLM verdicts are cached** in localStorage, keyed by (item, normalised answer), so a repeated answer costs nothing.

## LLM grader (`llm.ts`)
- `POST https://openrouter.ai/api/v1/chat/completions` from the browser, with the key read from Settings and `temperature: 0`. It asks for JSON output (with `response_format` json_schema where the model supports it, otherwise it extracts the JSON from the text), plus usage and cost reporting.
- **Input:** the task (produce or meaning), the English prompt or the French source, the reference answers, the learner's answer, the register, and the level (A1/A2/B1).
- **Output schema:** `{ verdict: "correct"|"wrong", corrected: string, errors: [{type: gender|agreement|conjugation|tense|accent|spelling|word-choice|word-order|missing|extra|meaning|register, wrong, right, explanation}], note? }`.
- **The prompt's rules:** accept any grammatical answer that keeps the meaning even if it differs from the reference; any accent error makes the answer wrong; tu/vous and on/nous are accepted unless `register` says otherwise; `corrected` makes the fewest edits to the learner's sentence; explanations are short, in English, at A2 level.
- **Settings screen:** the key in a password field, with Clear and "Test key". It explains that the key is stored on this device only and that the key should have an **OpenRouter credit limit** set. The site is published from a different GitHub account than the Greek app, so it has its own `<account>.github.io` origin and doesn't share localStorage with it.

### Phase 5: Core app

    *Result:*
    - **`normalise`:** NFC, lowercase, apostrophe look-alikes → `'`, non-breaking hyphens → `-`, and the space after an apostrophe dropped (`l' ami` = `l'ami`).     - **`compare(input, answers)`:** `correct` on an exact match after `normalise`, with no typo tolerance (`allez` ≠ `allons`, `allé` ≠ `allée`, `Dépêche toi` ≠ `Dépêche-toi`). `accent` when it matches only once accents are stripped (`allee`/`allée`, `a la`/`à la`, `coeur`/`cœur`), and `wrong` otherwise. An exact match beats an earlier accent-only one, and the matched answer is returned for the feedback.
    - **`tokenize`:** elided words are their own token (`l' j' d' m' t' s' n' c' qu' jusqu' lorsqu' puisqu' quoiqu'`), while `aujourd'hui`, `quelqu'un` and hyphenated words (`est-ce`, `A-t-il`) stay whole. Each token keeps its typed text for display plus its compare form.
    - **`diffWords(input, sentence)`:** an edit distance over tokens, where a right word costs 0, an accent-only one 0.5 and a wrong one between 1 and 2 by letter similarity, so a misspelt word pairs with its look-alike rather than a neighbour. Every sentence word is marked right, accent, wrong or missing, and extra typed words appear where they were typed. It's `correct` only if every word is right.
    - **Tests:** 59 pass (46 new), including every real sentence being a correct dictée of itself and every sentence, `altFr` and cloze answer matching itself, also with curly apostrophes. `npm run build` is clean.
